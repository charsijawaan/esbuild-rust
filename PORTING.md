# Experimental porting status

This is an experimental AI-agent conversion of esbuild to Rust. All Rust port
code is LLM-generated by OpenAI Codex agents using GPT-5.6 Sol. It is
unaudited, incomplete, and not an official esbuild project.

The current compiler feature checkpoint is `d7e50f9`, and the current evaluator
checkpoint is `5c5541c`, against upstream commit
`6ff1d8b0d8c134e867a397eef39702a223ebef9e` (esbuild 0.28.1).

Two deliberately separate engineering estimates are used:

- **About 55% of the whole esbuild product surface.** This includes the
  compiler, native API and CLI as well as serve, the long-running service
  protocol, JavaScript and Go API wrappers, WebAssembly, npm packages, and
  distribution tooling.
- **About 75% of the selected native compiler/bundler/API core.** This
  narrower estimate covers parsing, printing, resolution, linking, bundling,
  transformation, source maps, minification, native plugins, and native build
  contexts.

These are judgment-based progress estimates, not line coverage or an official
upstream compatibility metric. They are intentionally capped by known missing
features and by the absence of exhaustive upstream conformance and performance
testing. See [EVALUATION.md](EVALUATION.md) for the reproducible release-binary
matrix.

At this checkpoint the repository contains 114,040 physical lines across its
tracked `*.rs` files and 905 passing Rust tests. The bounded differential
evaluator passes 20 of 20 scenarios with matching runtime output against pinned
upstream.

Status values:

- `not started`: no Rust implementation
- `in progress`: partial implementation with known material gaps
- `substantial`: most package concepts are represented and focused tests pass,
  but completeness and package-level parity are not established
- `verified`: comprehensive package-level and integration parity demonstrated

All 25 production upstream `internal` package names have Rust counterparts.
This is a structural mapping metric, not a behavioral-parity claim.

## Material work still outside the checkpoint

- Serve and the JavaScript/Go service protocol are not Rust ports.
- WebAssembly, npm package wrappers, platform packages, and release tooling are
  not ported.
- The native context API supports rebuild and watch, but context cancellation
  and CLI watch/serve parity remain incomplete.
- Native plugins cover setup, resolve/load, lifecycle callbacks, nested
  resolution, plugin data, and watch paths; the upstream JavaScript plugin host
  and protocol integration remain outside this repository.
- Some public build/transform controls are still absent, including injection;
  property mangling, property reservation, and mangle caches; and
  build/transform color, log-level, log-limit, and log-override controls.
- Known target-compatibility gaps include optional chaining, nullish and
  logical assignment, array/object spread and object rest,
  default/rest/destructuring downleveling, async/await and for-await lowering,
  generator lowering, class fields and private syntax, compound exponentiation
  assignment lowering, and additional ES5 transforms. The port now lowers
  BigInt literals and plain exponentiation, and rejects unsupported
  generator/default/rest/destructuring and compound-exponentiation-assignment
  forms instead of emitting them unchanged.
- Explicit resource-management lowering, standard decorators, and import-glob
  bundling remain incomplete.
- Five CSS compatibility features remain table-only and unwired:
  `color-functions`, `gradient-interpolation`, `gradient-midpoints`,
  `is-pseudo-class`, and `nesting`.
- The full upstream test corpus, cross-platform filesystem matrix, security
  review, and performance benchmarks have not been completed.
